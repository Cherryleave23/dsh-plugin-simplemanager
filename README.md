# 插件管家（dsh-plugin-simplemanager）

> 适配内核：DSH `0.1.1-rc.2` ｜ 插件包版本：`0.1.1-rc.2`

> **0.1.1-rc.2 本版变更**：临时加载新增强健性——① **失败即中止**：依赖安装失败时立即停止装配并清理，不再加载出一个「半挂」的插件实例；② **先断开再拆除**：卸载时先把插件在运行期连入的路由 / 服务安全解绑，再移除装配登记，避免同类插件「热装 → 卸载 → 再热装」时路由冲突无法启动。

插件管家是 DSH 桌面壳内的一个**插件管理服务**，把「哪些第三方插件已安装、当前是否在运行、属于哪个分类、有没有备注、内核有没有新版本」统一到一个管理面板里。

一句话：**看得见插件状态、装得下 / 卸得掉、能先试用再正式装、收得干净。**

---

## 一、功能特性

- **运行状态一目了然**：每个插件卡片右上角用颜色徽标标示实时状态——运行中 / 加载中 / 待加载 / 启动失败 / 已卸载 / 卸载中。
- **一键停用**：点击插件卡片上的开关即可**停用**第三方插件，立即生效，**无需重启桌面壳**。（当前仅支持停用，暂不支持用开关重新启用。）
- **分类管理**：拖拽插件到自己的文件夹，可随时新建 / 重命名文件夹、给插件加备注、设显示名。
- **内核版本看板**：显示当前 DSH 内核版本，并提示是否有新版本（仅提示，不自动更新）。
- **先试用再安装（热插拔）**：插件可先在运行时临时加载试用，**不落盘、零残留**，重启桌面壳即彻底消失；试用满意后一键转为正式安装。
- **彻底卸载**：卸载后不残留，重启桌面壳也不会再出现。
- **官方插件只读保护**：官方内置插件默认只读展示，不提供停用入口，避免误操作影响内核。
- **重载前冒烟预检**：点「↻ 重载界面」前，会先在**内核进程**里逐层执行各活跃插件 client 的真实加载与挂载（无头冒烟），提前抓出「热注入没问题、但一刷新渲染进程就崩」的插件，并列出分步根因再让你决定是否重载。

---

## 二、快速开始

1. 打开桌面壳的 **设置 → 插件**，找到 **插件管家** 面板。
2. 打开面板后，你会看到 **「内核」** 区域（版本与更新）和 **「第三方插件」** 列表（已安装的第三方插件）。
3. 想先试用某个插件？点 **「+ 运行时临时加载插件」**，输入包名或本地目录路径即可。
4. 试用满意后，在临时插件卡片上点 **转正**，把它正式安装并持久启用。

## 三、安装指南

### 前置依赖

| 依赖 | 要求 |
| --- | --- |
| DSH 桌面壳 | 已登录并正常运行的桌面壳 |
| DSH 内核 | `0.1.1-rc.2`（本版本适配目标） |
| node | ≥ 20 |
| pnpm | ≥ 9 |

### 安装插件

本插件通过官方 `dsh plugin add` 安装到 profile，依赖闭包由 pnpm 自动落实：

```sh
# 安装到当前 profile
dsh plugin add "file:D:\path\to\dsh-v0.1.1-rc.2"

# 安装到指定 profile
dsh plugin --profile <name> add "file:D:\path\to\dsh-v0.1.1-rc.2"
```

> 路径 `file:D:\path\to\dsh-v0.1.1-rc.2` 指向**含 `package.json` 的版本目录**。安装完成后即可在桌面壳的插件列表里打开「插件管家」使用。

### 卸载插件

```sh
dsh plugin remove dsh-plugin-simplemanager
```

由官方命令移除依赖与装配登记，插件自身剩余的自持数据也会一并清理。

## 四、使用说明

### 面板入口

**设置 → 插件 → 插件管家。**

### 常见操作

| 我想… | 怎么做 |
| --- | --- |
| 查看内核版本 / 是否有更新 | 打开面板，看「内核」区域 |
| 把插件归到自己的分类 | 先「新建文件夹」，再把插件**拖拽**进该文件夹 |
| 记下某个插件的用途 | 在插件卡片上**添加备注**（内联编辑） |
| 停用一个第三方插件 | 点击插件卡片上的**开关**，立即生效，无需重启（暂不支持用开关重新启用） |
| 看某个插件的运行状态 | 看插件卡片右上角的**状态徽标** |
| 临时试用一个插件（不落盘） | 点「**+ 运行时临时加载插件**」，输入包名或本地目录；重启桌面壳后即彻底移除 |
| 让新加载插件的界面立即显示 | 点「**↻ 重载界面**」，只刷新界面、不重启桌面壳；重载前会自动预检各活跃插件的 client 是否可运行 |
| 把临时插件正式安装（转正） | 临时插件卡片上点 **转正**，写入装配清单，重启后仍然在 |
| 移除一个临时插件 | 重启桌面壳，临时插件即彻底移除（不落盘） |
| 查看官方内置插件 | 「官方内置」分类下只读浏览，开关不可用 |

### 安装与装卸的完整流程

**试用一个新插件（推荐流程）**

1. 打开插件管家 → 「+ 运行时临时加载插件」→ 输入插件包名或本地目录。
2. 插件被**临时加载**，卡片显示「临时」徽标，此时可正常试用、打开。
3. 试用满意 → 点卡片上 **转正**，插件被正式写入装配清单并持久启用。
4. 试用不满意 → **重启桌面壳**，临时插件自动消失，磁盘零残留。（临时加载的插件无法单独移除，只能通过重启清空。）

**永久移除一个已安装插件**

1. 面板里找到该第三方插件卡片。
2. 点卡片上的 **卸载**。
3. 卸载完成后芯片不再显示该插件；**重启桌面壳**确认已彻底移除、不再重现。

> 提示：卸载会一并清除该插件的依赖闭包与装配登记；若该插件仍有未保存数据，卸载前请先确认。

### 重载界面为什么多了一道预检

「热注入没问题、但一刷新界面就崩」的插件，靠静态检查（文件在不在、非不非空）拦不住——它的 client 得真跑一遍才会露馅。因此**重载界面前**，插件管家会先在内核进程里无头执行一遍各活跃插件的 client（`load` 注册 → `factory` 物化 → `apply` 挂载）：

- **全部通过** → 仍会确认一次后刷新渲染进程。
- **发现可能崩的插件** → 弹出的对话框会列准是哪个插件、磕在哪一步（读取 / 模块求值 / 注册契约 / `apply` 挂载）以及具体原因，由你决定是**仍重载**还是先修插件（当前不硬阻止）。

> 预检目录会自动匹配插件的真实出处（临时加载按源目录、正式安装按 profile），不依赖桌面渲染进程是否在跑即可预判。
> 当前预检做到「注册 + apply」两层；**模拟沙箱环境**（react-dom 挂载验证、官方运行时真实仿真）与**硬阻止重载**为后续演进方向。
