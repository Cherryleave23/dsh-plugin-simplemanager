# pm_* 工具明细与易错点

主流程见同目录 `workflow.md`。本节逐工具给出完整语义与参数说明。

## pm_status
- 输入：插件包名或 entryId
- 输出：是否在场、运行 phase、作用域、是否能热装、依赖闭包、挂起服务、是否有可回收残留
- 用途：闭环的「眼睛」，调试时/回收前确认状态

## pm_tempLoad
- 输入 spec 三种形态：① registry 包名 `foo` 或 `foo@版本`；② 本地插件目录绝对/相对路径；③ `file:`/`link:` 前缀路径
- 内部走「装齐依赖 → 解析真实包名 → loader.create 装配 → 登记临时态」，返回逐步结果与终态 `outcome`（pass 可调试 / pending 门禁挂起 / fail 失败）与 `residue` 残留
- 失败任一环自动回滚
- 可热装前提：第三方（非官方/壳组件）、含规范 package.json（name + 可加载 main/exports）、inject 服务当前宿主可满足、本地路径纯 ASCII
- **换键（重要）**：同名二次热装时，为避开宿主无法回收的 Node 模块缓存，会自动复制临时副本到 `.dsh-hot/<名>-hotN` 并改写其包名后装配，源码目录零改动。返回名因此可能带 `-hotN`，是预期机制，**不是错误**。换键带来几个开发态影响需知悉：① 用包名做键的插件状态（session/channel 路由/持久目录）落在副本名下，与原名的数据隔离不互通；② 产物内引用自身原名的处（license/Map 校验/签名）改名后可能失配。副本用后即删（pm_tempRemove）不累积。**转正（pm_promote）后以原名持久，不再走副本**
- 带前端板块的插件，返回里会有 `hint` 引导：仅当改动需用户在面板肉眼查看时才调 reloadClient

## pm_tempRemove
- 输入：此前 pm_tempLoad 返回的 packageName 或 entryId
- 拆运行时 entry + 回收闭包依赖 + 清理登记（含删除换键副本目录），期望残留为零
- 不要用原名（同名热装后原名可能已不代表当前装配），用**最近一次返回的 packageName**

## pm_promote
- 输入：插件包名
- 把临时加载的插件转正为持久装配（写 patch + 登记 bundles），重启后仍生效

## pm_uninstall
- 输入：包名 + 可选 `clearData`（默认 false）
- 移除装配登记 + 物理移除包与依赖闭包
- `clearData: true` 时才额外清除该插件落在 `~/.dsh` 的自持数据目录（配置/凭据/缓存）
- clearData 场景：彻底告别该插件、或它存过凭据敏感数据需一并清掉时

## pm_verifyPreflight
- 输入：specs 数组（包名/路径/file:，会先解析成包名）
- 做基础三态门禁预检：注入服务可达性、装配/重载是否挂起
- 无 VM 沙箱渲染，安全只读、不落盘不装配
- 每个热装前必做的第 0 步；outcome 非 pass 时先修再装

## pm_reloadClient
- 无参数
- 触发前端渲染进程刷新（重载界面）：仅刷渲染进程、不重启内核，会话与热装状态保留
- 零检测、零阻塞：不预检 client、不弹确认
- 由渲染进程常驻轮询消费信号，任意时点触发都能生效，不依赖面板是否打开
- 适用范围：插件带前端板块、且改动需用户在面板肉眼查看新前端时；纯内核改动无需调用
