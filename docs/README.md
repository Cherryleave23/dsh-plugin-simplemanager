# 插件管家（dsh-plugin-simplemanager）

> 适配内核：DSH `0.1.2-alpha.1` ｜ 插件包版本：`0.1.2-alpha.1-v1`

> **0.1.2-alpha.1-v1 本版变更**：适配 DSH 内核 `0.1.2-alpha.1`（大规模架构重组）——仅一项 client 配置迁移：客户端注入从已移除的 `@deepseek-ai/dsh-client-runtime` 迁到承接包 `@deepseek-ai/dsh-client-ui-renderer`（`ctx.slots` 服务名保留）。其余破坏项（`ctx.api` 移除、`CallId→ToolCallId`、`code-dispatch-log→ptc-dispatch-log` 等）消费面零命中，无需代码迁移。功能特性不变。

插件管家是 DSH 桌面壳内的一个**插件管理服务**，把「哪些第三方插件已安装、当前是否在运行、属于哪个分类、有没有备注、内核有没有新版本」统一到一个管理面板里。

一句话：**看得见插件状态、装得下 / 卸得掉、能先试用再正式装、收得干净。**

---

## 一、功能特性

- **运行状态一目了然**：每个插件卡片右上角用颜色徽标标示实时状态——运行中 / 加载中 / 待加载 / 启动失败 / 已卸载 / 卸载中。
- **一键停用**：点击插件卡片上的开关即可**停用**第三方插件，立即生效，**无需重启桌面壳**。（当前仅支持停用，暂不支持用开关重新启用。）
- **分类管理**：拖拽插件到自己的文件夹，可随时新建 / 重命名文件夹、给插件加备注、设显示名。
- **内核版本看板**：显示当前 DSH 内核版本，并提示是否有新版本（仅提示，不自动更新）。
- **先试用再安装（热插拔）**：插件可先在运行时临时加载试用，**不落盘、零残留**，重启桌面壳即彻底消失；试用满意后一键转为正式安装。
- **彻底卸载**：卸载后不残留，重启桌面壳也不会再出现。
- **官方插件只读保护**：官方内置插件默认只读展示，不提供停用入口，避免误操作影响内核。
- **重载前冒烟预检**：点「↻ 重载界面」前，会先在**内核进程**里逐层执行各活跃插件 client 的真实加载与挂载（无头冒烟），提前抓出「热注入没问题、但一刷新渲染进程就崩」的插件，并列出分步根因再让你决定是否重载。
- **工具管理**：把所有注入给 agent 的工具统一管起——默认直接列出全部工具（未分组），点「扫描分组」自动按插件管理的**文件夹层级**把可判定的工具归档到所属插件卡；支持**自定义工具组卡**、查看工具描述与参数、拖拽改归属、搜索过滤。

## 二、快速开始

1. 打开桌面壳的 **设置 → 插件**，找到 **插件管家** 面板。
2. 打开面板后，你会看到 **「内核」** 区域（版本与更新）和 **「第三方插件」** 列表（已安装的第三方插件）。
3. 想先试用某个插件？点 **「+ 运行时临时加载插件」**，输入包名或本地目录路径即可。
4. 试用满意后，在临时插件卡片上点 **转正**，把它正式安装并持久启用。

## 三、安装指南

### 前置依赖

| 依赖 | 要求 |
| --- | --- |
| DSH 桌面壳 | 已登录并正常运行的桌面壳 |
| DSH 内核 | `0.1.1-rc.2`（本版本适配目标） |
| node | ≥ 20 |
| pnpm | ≥ 9 |

### 安装插件

**一条命令即可安装，开箱即用**——它会自动从 npm 解析并落实插件依赖闭包、装配到 profile 并持久启用，无需重启桌面壳，也无需再做任何手动步骤：

```sh
dsh plugin add dsh-plugin-simplemanager
```

装完直接打开桌面壳 **设置 → 插件 → 插件管家** 即可使用。

> 指定 profile 安装：`dsh plugin --profile <name> add dsh-plugin-simplemanager`。
> 版本说明：默认安装 npm `latest`，持续收到最新功能修复；需要锁定内核适配版本时显式指定，如 `dsh plugin add dsh-plugin-simplemanager@0.1.1-rc.2`。

### 卸载插件

```sh
dsh plugin remove dsh-plugin-simplemanager
```

由官方命令移除依赖与装配登记，插件自身剩余的自持数据也会一并清理。

### 安装与装卸的完整流程

**试用一个新插件（推荐流程）**

1. 打开插件管家 → 「+ 运行时临时加载插件」→ 输入插件包名或本地目录。
2. 插件被**临时加载**，卡片显示「临时」徽标，此时可正常试用、打开。
3. 试用满意 → 点卡片上 **转正**，插件被正式写入装配清单并持久启用。
4. 试用不满意 → **重启桌面壳**，临时插件自动消失，磁盘零残留。（临时加载的插件无法单独移除，只能通过重启清空。）

**永久移除一个已安装插件**

1. 面板里找到该第三方插件卡片。
2. 点卡片上的 **卸载**。
3. 卸载完成后芯片不再显示该插件；**重启桌面壳**确认已彻底移除、不再重现。

> 提示：卸载会一并清除该插件的依赖闭包与装配登记；若该插件仍有未保存数据，卸载前请先确认。

### 重载界面为什么多了一道预检

「热注入没问题、但一刷新界面就崩」的插件，靠静态检查（文件在不在、非不非空）拦不住。因此**重载界面前**，插件管家会先在**内核进程**里对每个活跃插件的 client 做无头冒烟预检：

- **读 + 求值 + 物化** client bundle，判定装配契约（`load` 是否按契约注册单例 entry、`factory` 是否导出 `apply`/`inject`）；
- **注入服务门禁**：用**真实的 `@deepseek-ai/cordis`** `ctx.get()` 判定插件 `inject` 的每个服务在真实 ctx 上是否可达（`effect/on/拼错的服务名` 等会自然判缺失）。profile 解析不到真实 cordis 时回退三态近似。缺服务 ⇒ 重载必挂起（`pending`）整页被门禁打回。

- **全部通过** → 仍会确认一次后刷新渲染进程。
- **发现可能崩的插件** → 弹出的对话框列准是哪个插件、磕在哪一步（读取 / 模块求值 / 注册契约 / 服务门禁）以及具体原因，由你决定是**仍重载**还是先修插件（当前不硬阻止）。

> 预检目录会自动匹配插件的真实出处（临时加载按源目录、正式安装按 profile），不依赖桌面渲染进程是否在跑即可预判。
> 预检只做「契约 + 门禁」，**不 mock 运行** `apply`/渲染/数据驱动——那些是虚构环境、会误伤干净插件。插件真实运行是否崩溃，交由**独立子进程真机试运行（guard 式探针）**兜底判定。

### 工具管理

工具管理把所有注入给 agent 的工具统一成一张张可操作的卡片，开关与分组彼此**解耦**——不扫描也能正常用。

- **默认形态（未分组）**：进入「工具管理」面板即自动列出**全部**工具，落在「未分组 / 未知工具」大卡里，不主动做任何归组。
- **扫描分组（增强按钮）**：点「**⛁ 扫描分组**」，插件管家会额外扫描已装第三方插件的产物，把**可判定**的工具自动归档到所属插件卡，并按插件管理的**同一套文件夹层级**排布（你之前建立的文件夹在工具管理里也一致）。工厂动态命名 / 来源不明的工具归不进插件，仍留在「未分组」。
- **开关控制注入**：每个工具（含整卡总开关）都能单独开关。**关闭后该工具的描述不再注入 agent 的 system prompt**，可省 token；你的开关设置会被持久化，并随真实可见工具对账，失效工具自动清理。
- **自定义工具组卡**：可新建自己的「工具组卡」做快捷分组，卡片仅在此页可见、不进插件管理页；也可重命名、删除（删除后其中工具回到未分组）。
- **拖拽改归属**：把工具直接拖到任意插件卡 / 工具组卡 / 未分组，归属会持久化；下次进入仍保持。
- **查看与搜索**：点按卡片展开工具，点击工具名可看**描述与参数**；顶部搜索框支持按工具名 / 描述 / 插件名 / 别名 / 备注 / 卡名模糊匹配。

> 说明：工具管理只调整**注入可见性**与**分组展示**，不改动工具本身的功能注册；某工具真实不存在时相关记录会自动清掉，不产生「幽灵」开关。
